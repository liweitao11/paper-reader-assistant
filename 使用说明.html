paper-reader-assistant
完整使用说明

面向 Zotero、Obsidian、PDF、本地文档、云端 AI 与 Ollama 本地模型的一体化论文阅读记录工具。本文详细说明每个按钮、数据保存位置、模型内存行为与页面关闭链路。

版本目录：paper-reader-assistant助手端口：8774独立 Ollama 端口：11436模型目录由用户选择
1. 系统概览

paper-reader-assistant不是一个单独打开的静态 HTML 文件。双击启动器后，Python 在本机启动一个只监听 127.0.0.1 的小型服务，再由浏览器显示界面。浏览器负责交互，Python 负责读取 Zotero、选择本地文件、调用模型和写入 Markdown。

双击 PaperReader.cmd→pythonw.exe 后台运行→打开本地网页→填写或 AI 分析→生成 Obsidian 笔记
为什么看不到 Python 黑窗口？ 启动器优先使用 pythonw.exe，因此后台运行时不会出现命令行窗口。这是预期行为。
  • 不需要 Flask。
  • Zotero 数据读取可离线完成。
  • 本地模型分析可完全离线。
  • 云端 AI 需要网络、API Key，并可能产生费用。
  • Obsidian 输出是普通 Markdown，可长期迁移。
2. 启动与界面

启动

  1. 双击 PaperReader.cmd。
  2. 程序使用可用的 Python 运行时启动。
  3. 默认浏览器打开 http://127.0.0.1:8774。
  4. 若端口已有旧进程，应该先关闭旧助手，再重新启动。

界面区域

左侧/主区域

论文基础信息、研究问题、方法、创新点、结果、局限、研究启发和星级评价。

右侧 Zotero 栏

读取本机 Zotero 主文献，支持搜索、刷新、回填和折叠为可拖动的 Z 球。

AI 球与 AI 面板

AI 球可拖动并靠边；展开后可拖动面板标题栏，桌面端还可从右下角调整面板大小。二者都会记住位置。

右上角语言条与红色 ×

语言条在中文太阳与英文星星模式之间切换；红色 × 全局关闭模型服务、Python 后台和当前助手页面。

中英语言系统

默认中文。语言条下方用另一种语言提示切换方向；中文显示 Q 版太阳，英文显示 Q 版星星，日夜过渡只作用于条状控件。选择会保存在浏览器本地。切换界面不会清空或翻译已有表单内容；之后发起的 AI 分析默认使用当前界面语言填入空字段。

窗口变窄时 Zotero 面板自动收为圆形悬浮球。悬浮球可拖动，松开后自动靠边，避免遮挡表单。Zotero 面板和悬浮球始终高于普通表单；右上角语言/关闭控件位于 Zotero 之上、AI 面板之下；AI 面板和 AI 球位于最上方。窄窗口下 Zotero 面板会下移并自适应可用高度，避免收起按钮与全局关闭按钮重叠。窗口缩放后，AI 球与面板会自动限制回当前可视区域。

3. Zotero 与本地文档读取

Zotero 读取

程序以只读方式访问用户目录下的 Zotero/zotero.sqlite，不会修改数据库。Zotero 打开并锁定数据库时，程序使用不可变只读连接读取。

  • 读取题目、作者、期刊/会议、年份、标签和所属分类。
  • 过滤附件、笔记、批注和回收站项目，只显示主文献。
  • 点击文献后回填基础字段，并通过 zotero:// 定位 Zotero 条目。
  • 若检测到已下载 PDF，同时记录其路径供 AI 阅读。
  • “研究方向”不是 Zotero 的统一标准字段，因此不强制从 Zotero 回填。

读取本地文档

支持 PDF、DOCX、Markdown 和 TXT。PDF/DOCX 优先读取文件内嵌的题目、作者、年份与主题；缺少题目时使用文件名，不联网猜测缺失信息。

读取本地文档只导入当前表单，不会自动把文件写进 Zotero 数据库。直接写 Zotero SQLite 可能损坏文献库，因此程序坚持只读。

PDF 正文提取

Zotero PDF 优先使用同目录的 .zotero-ft-cache，速度快且离线。其他 PDF 尝试使用 pypdf。扫描件若没有文字层，需要 OCR，当前版本不会凭空识别图片文字。

4. 填写、创新点、清空与星级

表单内容

包含基本信息、研究背景、研究缺口、数据来源、技术路线、核心方法、实验指标、主要结论、论文不足、可借鉴方法、未来方向和一句话总结。

动态创新点

默认显示两个创新点。点击“添加创新点”可继续增加；每项都可单独删除。生成 Markdown 时会按实际数量编号，不再限制为两个。

星级评价

创新性、工程价值和相关性初始都是“未评价”。可人工选择一至五星，也可由 AI 自动填写。相关性会参考表单中的研究方向和标签；没有研究背景时应保持未评价。

AI 不覆盖规则

AI 只填当前为空的输入框、空白创新点和“未评价”的星级。已经人工填写的内容和已经选择的星级不会被覆盖。

一键清空

清除全部表单内容，创新点恢复为两个空项，三个评分恢复“未评价”，当前 AI 文档路径也会清除。Obsidian 中已经生成的笔记不受影响。

5. Obsidian 目录与输出格式

选择目录

首次提供一个默认论文目录，也可点击“选择 Obsidian 目录”切换到其他仓库或文件夹。最近一次选择写入 config.json，下次自动沿用。

文件名

格式为 YYYY-MM-DD_论文标题.md。Windows 非法字符自动替换。同名文件不会覆盖，而是追加 _2、_3。

笔记结构

  • YAML：题目、作者、期刊、年份、标签和日期。
  • 紫色章节标题，保持克制。
  • 正文使用 Obsidian 原生 callout 框，无需额外主题。
  • “1. 基本信息”是独立 Markdown 标题，信息框位于标题下方。
  • 评分以表格形式写入；未评分时显示“未评价”。
网页底部的“论文阅读时间指导”只用于阅读参考，不会写入 Markdown。
6. 云端 AI、提供商与 API Key

支持的接口

  • OpenAI / ChatGPT API：默认云端接口，默认模型 chat-latest。
  • DeepSeek 官方 API。
  • 豆包 / 火山方舟官方 API。
  • 自定义 OpenAI Chat Completions 兼容接口。

API Key 生命周期与可选保存

默认不保存：在当前网页打开期间输入一次，可连续分析多篇论文；刷新或关闭后清除。若勾选“保存此接口的 API Key”再分析，程序会用 Windows DPAPI 按当前登录用户加密后写入 config.json，下次选择同一提供商时自动载入。其他 Windows 用户无法直接解密。取消勾选并执行分析，会删除该提供商已保存的 Key。

保存仍需谨慎。 加密能避免配置文件出现明文，但无法抵御已经控制当前 Windows 账户的恶意程序。共享电脑、公共电脑和高保密项目建议保持不勾选。
ChatGPT Plus/Pro 订阅不等于 OpenAI API 额度。 云端 API 通常需要单独创建 API Key 并按量计费。

上传什么

程序提取论文文字并发送给所选云端服务商，不直接上传整个 Zotero 数据库。长文档会保留首尾并截断中间内容以控制上下文和费用。使用前应确认论文授权、保密要求和服务商隐私条款。

固定输出与语言

模型被要求只返回固定 JSON，包括研究方向、背景、问题、方法、创新点、结果、局限、启发、标签和三个星级。“AI 填空语言”可选“跟随当前界面（默认）”、中文或 English。因此中文界面也能单独要求英文结果，反之亦然。无证据的信息应返回空字符串，不能编造。

7. Ollama 与本地模型管理

Ollama 是什么

Ollama 是本地大语言模型运行器，负责下载、保存、加载模型并提供本机 API。论文内容在电脑本地处理，不发送给 OpenAI、DeepSeek 或豆包。

运行时与模型文件分离

可正常安装 Ollama，也可将完整 Windows 独立运行时放入 runtime 文件夹。模型目录不固定在程序内部：首次使用必须自行选择磁盘和文件夹，适合复制给其他人使用。

独立服务

本程序在 127.0.0.1:11436 启动独立 Ollama 服务，并通过 OLLAMA_MODELS 指向用户选择的目录，不干扰系统默认的 11434 服务及旧版 11435 服务。

模型下载

模型管理页提供 Qwen2.5、Llama 3.x 和 DeepSeek-R1 的多种大小。下载在后台执行，完成后自动切换本地模型分析页面。模型可达数十 GB，应确保磁盘空间和网络稳定。

已有模型

选择的已有目录应是 Ollama 模型库，通常包含 manifests 和 blobs。单独的 GGUF 文件不能直接作为 Ollama 模型库，需先用 Modelfile 注册。

规模典型下载量最低建议内存使用感受
1.5B–3B约 1–2 GB8 GB速度快，适合提取和简单摘要。
7B–8B约 4.7–5 GB16 GB入门论文总结；CPU 可运行但较慢。
14B约 9 GB24 GB科研分析质量更好，建议 10–12 GB 显存。
32B约 20 GB48 GB推理更强，建议 20–24 GB 显存。

配置是常见量化模型的经验建议。上下文越长，内存占用越高；没有独显也能 CPU 推理，但大型模型可能非常慢。

8. 模型、上下文与数据生命周期

一篇论文是否需要上下文？

需要。程序在单次请求中提供当前论文正文、固定分析格式，以及当前研究方向/标签。模型据此完成这一篇论文的阅读分析。

论文之间是否继承上下文？

不继承。每篇论文都是独立、非状态请求。上一篇论文的正文、推理过程和回答不会自动传给下一篇，避免文献之间相互污染。

模型何时进入内存？

第一次本地分析时，Ollama 将所选模型从磁盘加载到内存或显存。加载速度取决于模型大小、磁盘和硬件。

模型何时退出内存？

程序启动独立 Ollama 时设置 OLLAMA_KEEP_ALIVE=-1，所以模型默认持续驻留，便于连续分析。以下操作会释放：

  • AI 本地模型区点击“关闭模型并释放内存”：只卸载当前模型。
  • 页面右上角红色 ×：关闭整个助手和独立 Ollama 服务。
  • 正常关闭助手页面并确认离开：关闭后台和独立 Ollama 服务。
  • 结束 Python 助手进程：服务进入清理阶段并终止其管理的 Ollama 进程。

释放是否删除模型？

不会。释放只清理 RAM/VRAM。模型权重仍保留在用户选择的目录，下次分析只需重新加载，无需下载。

论文数据是否保存？

程序不建立 AI 聊天历史库。提取正文在请求期间存在于内存；只有用户点击“生成 Obsidian 笔记”后，结构化结果才保存为 Markdown。配置文件保存目录、所选本地模型名称，以及用户主动勾选后生成的 API Key 加密密文。

9. 关闭行为详解（重点）
结论：正常关闭主助手 HTML 页面并确认离开，会通知 Python 后台关闭；后台退出时会终止它启动的 Ollama 服务。模型文件不会删除。

A. 直接关闭浏览器标签页或窗口

  1. 页面的 beforeunload 事件触发。
  2. 浏览器显示自己的“离开网站”确认提示。出于安全限制，网页不能自定义该提示文字。
  3. 选择“取消”：页面不关闭，后台和模型继续运行。
  4. 选择“离开/确认”：浏览器开始关闭页面，随后触发 pagehide。
  5. pagehide 使用 navigator.sendBeacon('/api/shutdown')，即使页面正在卸载也尽量可靠地发送关闭通知。
  6. Python 收到请求，调用 HTTP 服务器的 shutdown()。
  7. serve_forever() 返回，进入 finally：关闭服务器，并终止本程序启动的 Ollama 子进程。
  8. 浏览器页面自然关闭；模型权重和笔记继续保留在磁盘。

B. 点击页面右上角红色 ×

  1. 先显示程序自己的确认框。
  2. 取消：不执行任何关闭。
  3. 确认：标记为程序主动关闭，避免再出现浏览器离开提示。
  4. 使用带 keepalive 的 POST 请求调用 /api/shutdown。
  5. Python 后台和独立 Ollama 服务按上述流程停止。
  6. 网页尝试执行 window.close()。
  7. 如果浏览器禁止脚本关闭普通标签页，程序会把页面替换为“paper-reader-assistant已关闭”结束页；后台已经停止，可以安全手动关掉该页。

C. 点击“关闭模型并释放内存”

调用 Ollama 的卸载接口，只卸载当前选中模型。Python、网页和 Ollama 服务继续运行，可以立即切换模型或继续使用其他功能。

D. 无法保证的异常情况

浏览器崩溃、任务管理器强制结束、系统断电、操作系统强制关机或安全软件阻断 Beacon 时，页面可能来不及通知后台。这是浏览器和操作系统层面的限制。遇到这种情况，可在任务管理器结束对应 Python/Ollama 进程；模型文件仍不会因此删除。

不要把关闭“使用说明”页面理解为关闭助手。 本手册是单独标签页，关闭它不会停止论文助手。只有关闭主助手页面，或点击主助手右上角红色 ×，才执行关闭链路。
10. 文件、配置与隐私
数据保存位置/生命周期是否上传
Obsidian 笔记用户选择的论文目录，长期保存程序不主动上传
本地模型权重用户选择的 Ollama 模型目录，长期保存下载自模型仓库；分析时本地使用
output_dir、model_dir、local_modelconfig.json不上传
API Key默认仅网页会话；主动勾选后以 Windows 用户级密文保存仅发给所选 API 服务进行鉴权
PDF 提取文字请求期间在内存云端模式会发送；本地模式不发送
Zotero 数据库原位置只读访问不整体上传

选择云端模型前，应检查论文是否涉及未公开实验、合作单位数据、商业秘密、个人信息或受限版权内容。本地模型适合高隐私场景，但仍需保护模型目录和生成笔记。

11. 常见问题排查

双击 CMD 没反应

确认使用英文名 PaperReader.cmd；程序会尝试 Codex 自带 Python、系统 pythonw.exe 或 python.exe。安全软件可能阻止脚本或本地端口。

页面打不开

重新双击启动器。若旧版本端口仍存在，使用当前版本地址 127.0.0.1:8774。不要直接双击 templates/index.html，因为保存功能需要 Python 后台。

Zotero 列表为空

确认 Zotero 数据目录在用户目录、数据库存在，且文献不是只有附件。点击“刷新”。Zotero 主文献和 PDF 附件的数量不同是正常的。

本地 PDF 没有作者/期刊

许多 PDF 没有正确内嵌元数据；离线情况下程序不会猜测。可从 Zotero 导入或人工填写。

本地模型下载失败

确认已安装 Ollama 或完整运行时位于 runtime，已选择模型目录，磁盘空间充足，网络能访问模型仓库。

选择已有目录却找不到模型

目录必须是 Ollama 模型库结构。单个 GGUF 文件需要先注册。若独立 11436 服务被旧进程占用，应先关闭旧助手。

AI JSON 解析失败

小模型可能不稳定遵守 JSON 格式。尝试 Qwen2.5 7B/14B 或更强模型；也可降低论文截取长度或改用云端模型。

扫描 PDF 无正文

扫描件需要 OCR。先用 Zotero、Adobe、OCRmyPDF 等工具生成文字层，再导入。

红色 × 没关掉标签页

浏览器可能禁止脚本关闭非脚本创建的标签页。只要出现“助手已关闭”结束页，后台和模型服务已经停止，手动关闭标签即可。

12. 推荐论文阅读工作流
  1. 双击 PaperReader.cmd。
  2. 从 Zotero 选择已下载论文，或点击“读取本地文档”。
  3. 检查题目、作者、期刊、年份和标签。
  4. 选择云端或本地 AI。涉及敏感内容时优先本地模型。
  5. 填写研究方向和标签后运行 AI，以便评价相关性。
  6. 人工核对 AI 提炼的研究问题、方法、创新点、结果与星级。
  7. 补充“对我的研究启发”，这是最需要个人判断的部分。
  8. 点击“生成 Obsidian 笔记”。
  9. 点击“一键清空”，继续下一篇。
  10. 全部完成后点击主页面右上角红色 ×，关闭模型、后台和页面。
AI 是结构化阅读助手，不是事实裁判。实验数字、对比结论、局限和引用位置都应回到原文核对。
